# 完成前验证

## 职责

让每个重要的完成或交付声明都对应当前生命周期边界上的最新直接证据，并准确报告证据实际支持的范围。

这个 Skill 用来纠正“工作看起来结束了，就把局部成功推断成整体完成”的默认行为。验证服务于声明可信度，不以执行命令或测试的数量证明认真程度。最低成本的充分证据是正确结果；证据只覆盖局部时，部分完成也是准确结果。

## 声明与直接证据

先拆分准备作出的声明。每个边界分别成立，前一个边界成功不能证明后一个边界成功。

| 声明边界 | 典型直接证据 |
| --- | --- |
| 本地实现或文档完成 | 最终差异、目标内容以及与改动相称的行为或静态检查 |
| 测试、类型检查或构建通过 | 最后一次相关修改后目标命令的退出状态、关键输出和实际执行范围 |
| 已提交 | 当前仓库的提交记录、提交内容和工作树状态 |
| 已推送 | 目标远端引用包含预期提交 |
| 合并请求已创建 | 目标平台存在指向预期分支和提交的合并请求 |
| 合并请求已合入 | 目标平台的合入状态以及目标分支包含预期提交 |
| CI 通过 | 目标提交对应流水线和必要任务的当前结果 |
| 制品已发布 | 目标仓库中版本、摘要或标签的实际记录 |
| 已部署 | 目标环境报告的发布版本、提交或制品摘要 |
| 线上行为已验证 | 目标环境上的直接请求、业务结果、日志或指标 |

任务报告、历史日志、旧测试结果和“按理会成功”可以帮助选择检查，不能替代当前声明的直接证据。

## 执行流程

1. **列出声明。** 写清准备向用户确认的结果及其边界，例如“目标测试通过”“本地修复完成”或“目标版本已部署”，避免使用无法判断范围的笼统完成表述。
2. **选择直接证据。** 为每条声明选择成本最低但足以证明它的检查。根据改动风险组合内容检查、定向测试、集成测试、类型检查、代码规范检查、构建和运行时验证。
3. **取得最新结果。** 在最后一次相关修改后运行检查，读取退出状态、关键输出、实际选择的测试和目标环境。并行检查分别等待到明确结束。
4. **解释证据强度。** 必要检查失败时，该边界的完成声明不成立；检查因环境、权限或依赖无法执行时，该边界保持未验证，并说明取得完整结论还缺什么。
5. **处理被削弱的结果。** 检查跳过、重试后才通过、出现警告、存在未关闭句柄或只覆盖部分目标时，判断它们是否影响声明。保留已被证明的较小结论，同时明确不稳定性或覆盖缺口。
6. **复核最终状态。** 检查最终差异、未跟踪文件、暂存范围和工作树，确认交付内容与任务范围一致。格式化、代码生成、快照更新等检查改变文件后，重新复核差异，并重跑受这些变化影响的证明性检查。
7. **逐边界确认交付状态。** 提交、推送、合并请求、CI、制品、部署和线上行为分别读取对应系统的当前结果。执行这些动作本身服从用户授权和专门流程；本 Skill 只确认每项声明是否已有直接证据。

## 风险缩放

- 小型文档、提示词或机械改动可以用目标内容检查、格式或解析校验和最终差异证明。
- 局部业务行为使用定向测试或目标调用，并按编译边界补充类型检查或构建。
- 共享库、公共 API、持久化、队列、权限、并发和跨模块行为需要覆盖失败机制的定向验证及与影响相称的回归。
- 发布、部署和生产行为使用对应环境的直接证据，代码测试只证明发布前的代码边界。
- 每项新增检查都对应一个尚未证明的重要声明或真实风险。证据已经充分时结束验证。

## 输出方式

按声明报告结果：

- **已证实**：列出直接证据、时间相关性和覆盖范围。
- **未证实或已否定**：列出失败、无法执行、仍在运行或被跳过的检查，以及它阻止了哪项声明。
- **剩余边界**：只记录会影响用户理解完成状态的风险和后续生命周期。

当所有准备作出的声明都有充分直接证据，或证据不支持的声明已经明确收回时，完成验证。

## 与相邻 Skill 的边界

- `test-driven-development` 负责测试策略、回归保护和 TDD 循环。
- `code-review` 负责候选能否合入的独立判断。
- 发布、部署和运行操作 Skill 负责执行对应动作并处理权限与恢复。
- 本 Skill 负责验证声明，不因“准备验证”自动取得提交、推送、发布、部署或生产写入权限。
