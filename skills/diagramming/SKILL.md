# 图解

让读者通过图理解一个问题，沿分支知道发生什么，并能判断规则为何这样设计。图的内容、关系和阅读顺序先成立，再用 draw.io 把它做成可编辑、可检查的产物。

## 1. 确定图要帮助谁判断什么

阅读用户请求、已有决定、材料和现有图，明确读者、核心问题和用途。例如“达到什么条件就停止采集”需要条件与终点，“采集系统包括哪些能力”需要分类与层级。

沿用已经明确的范围、风格、交付格式和语言。解释现有图时先读取原图；局部文字修改聚焦对应节点及受同一含义影响的位置。事实缺口会改变分支或结果时，先取得必要来源，或在图中标明待确认状态。

## 2. 根据关系选择图形

| 读者要理解的关系 | 表达方式与读取材料 |
| --- | --- |
| 触发、动作、条件、先后、停止、恢复与结果 | 流程图；读取[业务图设计](references/business-diagrams.md) |
| 谁负责什么、系统如何协作、数据流向和边界 | 架构图或关系图；读取[业务图设计](references/business-diagrams.md) |
| 一个主题有哪些方面、概念怎样分类和展开 | 思维导图；读取[思维导图设计](references/mindmaps.md) |
| 总览与关键流程都需要 | 用总览建立阅读入口，再为需要解释的路径安排独立页面；按实际问题读取以上材料 |

用户明确选择图型时围绕该图型实现目标，并说明会影响理解的表达取舍。思维导图的父子线表示归属，流程箭头表示流转；混合任务按问题分开表达。简单 Mermaid 已满足当前阅读和维护需求时，可以沿用原格式；需要 draw.io 编辑或稳定图片时再转换。

## 3. 建立有来源的内容结构

从业务入口和真实场景梳理参与者、动作、判断与结果。源码、配置和原始记录证明当前行为；产品决定与设计记录解释已确认的理由。把当前实现、拟议方案、业务解释和待核实事项各自标明。

先形成能从头读通的结构，再安排图元：

- 每页围绕一个读者问题，页标题直接说明问题；复杂主题可用目录页、总览和细节页组织。页面数量与画布大小服从内容和用户阅读方式。
- 一个动作框表达一个动作，一个判断框表达一个能作答的问题。场景会产生不同结果时分别展开；必要的组合条件写明“全部满足”或“任意一项满足”。
- 关键规则交代作用对象、适用范围、触发时点与结果。时间、数量、缓存、权限等细节在改变业务结果或取舍时出现，并写清单位和计算范围。
- 用户需要评估规则合理性时，在对应判断附近或页下方解释业务目的、接受的代价和依据；备注能对应具体分支。详细来源放相邻说明，关键取舍保留在图内。
- 节点使用读者熟悉的名称和完整动作。首次出现的术语写出具体含义，例如“用平台名称和帖子 ID 识别同一条帖子”。代码名作为核对入口。

以真实例子检查结构：读者能从一个入口走到明确结果，知道继续哪一步、停止哪一部分，以及当前已取得的数据怎样处理。

## 4. 绘制或修改可编辑源图

`.drawio` 是权威源文件。新图采用原生、未压缩 XML，节点和连线均可单独编辑。已有图先读结构，保留本轮范围外的页面、节点 ID、含义和手工布局。

需要创建、转换或调整图元时，读取[draw.io 制作与工具](references/drawio-authoring.md)。其中集中维护草图样式、模板、脚本用法、嵌入源图恢复和导出参数。工具路径相对于本包解析，脚本和模板随同一个包维护。

新图默认使用程序员白板草图；已有图沿用其风格，用户指定风格时按要求调整。内容大纲和生成脚本是制作材料，手工编辑后的源图继续作为权威版本。

## 5. 按交付方式检查

先检查业务含义，再检查结构和实际显示：

1. 对照来源确认条件、分支、顺序、独立路径、范围和终点；从代表性入口各走一遍，核对边界值和当前页、批次或对象的处理结果。
2. 读取自带检查器输出的页数、标签、节点 ID 与边端点，核对唯一性和连接关系；页面导航另查源 XML 的链接目标或原生界面。思维导图还检查中心主题、父子层级与跨分支关系。修改时对照完整差异，确认业务含义和改动范围。
3. 实际查看渲染结果，检查文字完整、箭头可追踪、条件标签归属清楚、备注能找到对应分支，以及目标阅读比例下的可读性。结构检查与显示检查分别报告证据。

交付按用户的阅读方式选择：

| 交付要求 | 产物与显示检查 |
| --- | --- |
| 只看或只改源文件 | 交付 `.drawio`，直接在 draw.io 中检查受影响页面 |
| 图片、README 或分享材料 | 同目录交付 `.drawio` 与所需 PNG；实际查看 PNG，验证嵌入源图及两者同步 |
| 未指定，且正在新建图 | 默认交付源文件和同名 PNG；已有图沿用当前交付约定 |
| 只读解释 | 解释原图及其可确认范围，原文件保持 |

PNG 默认采用浅色主题、24 像素边距、2 倍缩放并嵌入源图；已有发布物优先沿用尺寸、主题与透明度。源文件交付时采用原生界面检查，图像导出只服务已选择的交付方式。显示工具暂不可用时保留源文件，说明已完成的结构检查及待查看的页面。

当内容准确、阅读路径清楚、对应交付产物可用且相关检查充分时结束。交付回复链接源文件及所需图片，简要说明阅读入口、主要改动和验证范围。
