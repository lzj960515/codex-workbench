# 业务拆解

结合用户当前提供的内容和已有对话，拆解用户指定的业务、代码、产品、方案或案例。单独调用时，以当前讨论对象为准；对象不明确时，先询问用户想拆解什么。

以理解它为目标，围绕下面三个问题展开，把背景、问题与解决方式之间的关系讲清楚。案例的好坏由实际证据支持；用户选择研究它，不代表它已经被证明有效。

## 1. 业务背景是什么？

说明它服务谁，发生在什么业务场景中，以及哪些需求、现有条件和现实约束促成了这个问题。结合材料中能够确认的背景解释，区分已知事实、合理推断和尚未明确的信息。

## 2. 想解决什么问题？

说明具体的困难或诉求，为什么需要解决，以及做到什么才算达到目标。区分业务目标与当前采用的方案，让读者先理解为什么需要这件事，再理解为什么采用这些做法。

## 3. 具体怎么解决的？

沿实际结构或流程，从输入、主要步骤到结果，解释各个环节承担的职责，以及它们怎样回应前面的目标和约束。

重点分析：

1. 它采用了什么结构或流程；
2. 哪些关键选择影响了结果，各自解决了什么问题、带来什么取舍；
3. 实际做法是否覆盖了前面的问题和完成标准，哪些效果已有证据，哪些仍待确认；
4. 哪些规律可以迁移，哪些细节依赖这个案例的特定条件。

涉及代码时，读取相关入口、调用关系、实现及必要的测试或文档，解释业务动作之间的联系。现有实现能证明当前行为；历史动机和设计意图需要相应依据，证据缺失时明确保留未知。目标与实际行为不一致的地方如实说明。

## 收尾

用简短总结串起“在什么背景下，为了解决什么问题，采用了什么做法”。有可复用规律时，提炼最有依据的几条并说明适用条件。

如果用户还希望从中学习并应用到自己的事情上，再结合用户的学习目标，给出可以执行的操作清单和一个最值得先尝试的小练习。解释深度随当前问题调整，完成拆解后按用户明确提出的评价、设计或实施请求继续。
