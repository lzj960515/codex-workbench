# 把话说清楚

让读者读完就明白核心事实、事情的来由，以及需要采取的行动。根据读者、用途和已有材料，选择合适的信息、结构与语气。

## 明确读者与用途

结合当前请求，确认这段文字给谁看，读者已经知道什么，希望理解、判断或完成什么。沿用已经明确的背景、结论、语言与篇幅要求，材料齐全时直接成文。

新写内容时，从读者关心的问题组织材料。修改已有内容时，先理解原意，保留有效事实、语气与表达，再修正影响理解的部分。用户只要求调整一句时，修改聚焦这句话及必要的衔接。

## 把事实与判断表达准确

采用当前任务已经核实的事实与来源，把事实、推断、建议和计划状态表达清楚。处理他人的反馈或报告时，结合实际观察与适用规则形成判断；原稿中的猜测作为待核实信息呈现。

需要核实关键前提时，先对照已有材料，再决定结论能说到哪里。材料支持部分结论时，讲清已经确认的内容，将其余关键事项写为“待核实”或“待确认”。预计效果与实际结果分别表达，日期、数值、条件和责任主体保持准确。

关键依据放在对应判断旁边，详细来源通过链接提供。内容的可信度来自事实及其适用范围，措辞的强度与证据相称。

## 按读者的理解顺序组织

开头直接回应读者关心的事实、判断或结果，再补理解它所需的背景与原因，最后说明影响、行动或下一步。需要解释专业机制时，先用具体情境或例子建立认识，再引入相关术语与技术细节。

让每段发展一个主要意思，用具体主体和动作连接因果。平行事项、步骤与比较适合列表或表格；连续推理使用连贯段落。章节服务于查找和阅读，简单回复用几句话即可。

读者已经提供的背景直接承接。篇幅由理解和决定所需的信息确定；重要约束、关键理由与适用条件完整保留。

## 用正向句式说明事情

全文采用正向句式，直接陈述事实、原因、结果、适用条件和做法。需要界定范围时，写清支持的对象、成立的条件或接下来的处理方式。

表达具体立场与选择依据，把读者的注意力放在实际问题和可采取的行动上。证据待补时明确所需材料，事情仍在推进时写清当前阶段与下一步。

例如，写“这项功能支持管理员，普通成员可向管理员申请操作”，清楚交代适用对象与处理办法；写“原始响应待核实，当前已确认页面展示为零”，分别说明观察结果与证据状态。

## 使用日常词与具体动作

采用读者熟悉的词，说明谁做了什么、作用于什么、产生什么结果。把“优化体验”“完善机制”等概括落实为具体变化：

| 要表达的内容 | 具体写法示例 |
| --- | --- |
| 操作步骤得到简化 | 提交申请后直接显示处理进度 |
| 付款重试行为改变 | 同一笔付款超时后重试，现在继续原交易 |
| 工作仍在推进 | 数据接口已经接通，下一步核对页面展示 |

专业术语用于提高表达精度，首次引入时说明它在当前情境中的含义。产品名、API、代码标识符、命令、文件名和路径保持准确写法；行内代码使用反引号，文件与证据通过可访问的链接引用。

正文使用读者的语言，词语搭配与句子关系符合该语言的习惯。语气与场景相称，表达自然、完整，必要的专业信息就近解释。

## 按文字的用途选择重点

| 场景 | 应讲清的内容 |
| --- | --- |
| 回复与问答 | 直接答案、必要原因、读者需要的行动 |
| 通知与说明 | 发生什么、影响谁、何时生效、怎样处理 |
| Issue、测试反馈与调查结论 | 实际现象、适用规则、有证据的判断、当前处理状态 |
| PR 说明 | 原场景的问题、选择理由、修改后的行为、验证范围 |
| 面向用户的 Changelog | 具体使用场景，以及现在的行为或可获得的能力 |
| 决策与维护记录 | 背景与问题、决定及理由、实际结果与边界 |
| 工作进展 | 已完成结果、新发现及其影响、下一项必要动作 |

采用当前用途需要的内容，形式与长度随问题调整。

## 交付前通读

从读者角度检查文字：

1. 开头回应当前问题，整段文字具有清楚的用途。
2. 事实、判断、状态与原始材料一致，原因与结果衔接自然。
3. 全文使用正向句式，词语具体，主体、条件和行动明确。
4. 每句话提供有用信息，细节与篇幅恰好支持理解或决定。

清理重复背景、空泛评价、套话和过程叙述，保留结论、关键理由、必要证据和适用边界。交付用户需要的正文；用户要求说明修改时，再概括有实质影响的调整。
