# Receiving Code Review

## 目标

把审查意见当作需要验证的技术输入。依据真实代码、业务约束和既有决策采纳正确建议，并纠正不适用或不准确的部分。

## 执行流程

1. 准确复述意见要解决的问题，区分目标、示例代码和建议实现。用户粘贴的类型、命名和术语是参考信号，除非用户明确要求逐字采用。
2. 阅读相关调用链、类型、测试、模块装配和已有架构决策，确认意见针对的行为是否真实存在。
3. 分类每条意见：确定 Bug、一致性问题、功能缺口、业务模型问题、架构债务或不适用建议。判断影响和修复边界。
4. 对确定问题实施符合现有结构的修复，并扫描同根因位置。对需要新业务语义或高风险架构调整的建议，说明证据、取舍和后续设计边界。
5. 当建议与代码事实冲突时，采用有证据的正确形式并简要解释关键修正。只有多个解释会显著改变业务、数据、安全或兼容性时才向用户确认。
6. 运行与改动风险相称的验证，确保不是为了满足评论文字而改变原有正确行为。

## 沟通方式

- 直接给技术结论，不做表演式认同或反驳。
- 多条意见按严重性和依赖顺序处理。
- 未采纳时指出具体代码证据、业务约束或成本，不用模糊偏好代替理由。
- 审查意见本身清晰且正确时直接实施，无需额外仪式或重复确认。
