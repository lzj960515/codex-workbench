# 软件开发回归用例

本集合整合原架构设计、代码实现和代码审查的 11 个场景。`origin_skill` 与 `origin_case_id` 记录迁移来源，业务请求、初态和预期结果继续保留；选用条件改为唯一的 `software-development` 入口。

- 架构：共享请求状态的归属、已有合理接口的保留。
- 实现：机械接线、取消业务归属、职责替换与旧路径退出、模型复用及数据授权。
- 审查：认可合法等价重构、识别真实租户隔离回归。

执行方法使用 `writing-for-ai` 的评估流程，按当前变化选择必要场景。执行端取得请求和初态，预期标准保留在评估端；日志、快照与评分放任务 `tmp/`。

原有 `check_outputs.py` 继续提供受控案例的产物检查。原版本的运行记录只说明当时的环境和能力组合；迁移保留用例不代表已经重新完成新入口或自动审查的行为评测。
