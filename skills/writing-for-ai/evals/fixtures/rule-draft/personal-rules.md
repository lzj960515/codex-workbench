# 用户规则

- 涉及新增、删除或改变表、持久化字段、字段含义、类型或约束，以及既有 JSON 或其他存储中的新持久化结构，先提交具体清单、必要性、复用比较与使用方影响，取得明确确认。
- 功能目标确认与数据变更确认分别记录；确认前继续独立工作，依赖新模型的实体、迁移、业务实现和结构性测试在批准后开始。
- 类和函数采用领域名字，每个类有一个稳定职责。
- 代码命名表达业务意图，让每个类负责一件事。
- 修改代码前理解调用者和完整业务流程。
- 改代码先看业务入口和下游使用方。

## 发布说明

发布前确认当前分支、版本与改动范围，运行项目已有检查，生成发布说明，发布后核对目标版本与结果。详细步骤保存在 docs/release.md，当前把这段内容也复制在个人规则中。
