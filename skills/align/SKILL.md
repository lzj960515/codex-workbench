# 理解对齐

检查自己是否理解了用户当前表达的意思，以及用户希望回答到什么程度、事情推进到哪一步。理解清楚时简短确认，有影响后续处理的疑问时向用户提问。

## 核对当前表达

1. 结合当前消息和已有对话，识别用户想解决的问题、希望得到的结果，以及本次要推进到哪一步。单独收到指令时，以最近正在讨论的事项为对象；上下文中没有对象时，先请用户说明想核对哪件事。
2. 按业务目标理解口述、简写和示例。区分用户已经确认的要求、用于说明想法的例子，以及留待以后考虑的候选；需要修正会影响含义的表述时，向用户说明当前理解。
3. 检查自己的理解是否还有影响结果、范围或处理程度的缺口。先复用已有信息；需要核实时只读取与该歧义直接相关的材料。区分用户已明确的意思和自己的推测。
4. 理解清楚时，可以直接说“理解了”；一句概括有助于核对时，用自然的一句话点出核心意思即可。确认的篇幅以用户能顺畅继续交流为准。
5. 有关键疑问时，直接问最影响后续处理的问题，必要时简短说明不同理解会造成什么区别。收到回答后更新理解，疑问解决就结束核对。

## 完成与后续行动

用户只要求核对理解时，以简短确认或必要的澄清问题完成本轮。用户同时明确要求执行任务时，先核对理解，再沿原任务授权继续；依赖关键澄清答案的行动等待用户回答。核对充分时直接结束这一环节，无需附加形式化确认。

本方法作用于当前请求及其必要澄清。后续话题按用户的新请求处理，讨论深度与文档产物服从当前任务需要。
