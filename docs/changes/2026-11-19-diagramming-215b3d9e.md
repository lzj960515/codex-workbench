# 图解统一流程图与思维导图的方法

用户在阅读业务流程时，需要看清每个条件会走向什么结果、什么时候停止，以及规则背后的业务目的。原 `drawio` 与 `mindmap` 共用文件、草图风格、读取恢复和导出流程，入口分别维护，而业务图的条件、边界与理由缺少完整指导。

本次采用 [diagramming](../../skills/diagramming/SKILL.md)，展示名“图解”。主稿维护读者问题、图型选择、来源、信息结构及交付流程；[业务图设计](../../skills/diagramming/references/business-diagrams.md)和[思维导图设计](../../skills/diagramming/references/mindmaps.md)按需读取，共同的风格和工具集中在[制作资料](../../skills/diagramming/references/drawio-authoring.md)。业务图明确单个动作与判断、组合条件、计数范围、停止对象和已取得数据的处理，并用备注说明目的、代价与依据。当前实现、已确认决定和用途解释分别表达，具体业务数值只作为例子。

原有原生编辑、Mermaid 转换、PNG 源图恢复、脑图生成及同步检查能力保留，两个脑图读取脚本改为定位本包工具。交付方式服从用户用途：源文件在原生界面检查，图片按需导出。旧两个 Skill 目录退出，README、metadata、安装器及既有安装用例同步采用新名称；本机只切换这次涉及的仓库托管链接。

候选已通过包格式、引用、资源保留及独立内容审查。一轮独立上下文使用候选完成业务流程源图，按需读取与分支表达已直接核对，自动发现和长期效果继续由实际使用积累证据。正式迁移通过现有安装与 Skill 契约的 26 个用例、脑图工具的 6 个用例，以及包格式、公开内容和差异检查；独立迁移审查通过。本机已核实新托管链接指向正式包、两个旧托管链接退出。
