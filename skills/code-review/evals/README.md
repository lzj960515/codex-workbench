# 评估案例

这里保存该 Skill 的自然请求、独立初态和预先确定的行为标准。案例根据用户反馈的偏差与现有职责构造，不是生产事故原样回放；当前为初始回归候选集。

使用 `skill-creator` 的评估流程，按行为变化选择相关案例。`evals.json` 中 fixture 路径相对本目录；执行端只取得 prompt 和 fixture，expectations 留在评估端。运行日志、评分与快照放本次任务的 tmp 目录。

评分同时检查最终回复、必要工具轨迹和文件变化。每项记录通过、失败或证据不足及引用；执行结束不代表行为通过。只读案例还要检查有无越界写入尝试，文件不变不能单独证明 Agent 自主遵守边界。

真实使用出现新的失误时，保留脱敏请求和必要初态，补成能复现该机制的案例。改变关键条件的不同分支值得新增；同义问法无需成批堆积。修改标准时说明用户目标或契约发生了什么变化。
