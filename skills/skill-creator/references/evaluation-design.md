# Skill 评估设计

本页用于已经按 SKILL.md 判定需要行为测试的改动，回答测什么、怎样评分、哪些案例值得长期保存。

## 明确比较对象

Skill 通过模型、Agent 工具与运行环境产生效果。评估结论表达为“这个运行环境中的这组 Skill，在这些任务上的表现”。

- **触发**：自然请求是否选择适当能力，相邻任务是否误触发。
- **任务结果**：选择能力后，实际文件、系统状态或交付判断是否满足契约。
- **协作**：问题发生在多个 Skill 之间时，保留实际组合，检查交接、信息归属和停止边界。

按问题选择层次。显式指定 Skill 可以检验正文行为，但自然触发要使用未点名 Skill 的请求。执行 Agent 只取得任务和必要输入，预期答案与评分标准保留在评估端。

更新 Skill 时比较修改前完整包与候选；新增 Skill 时可比较包含与不包含它的组合。其余相关 Skill、模型、推理强度、工具、初态和全局规则保持一致。联合修改多个 Skill 时，结论归于这组改动；需要归因到其中一个时，再做单项对照。

运行环境或评分规则发生变化时，重新建立可比基线。闭源系统提示和服务端变化可能无法固定，记录这些限制；CLI 运行证据按 CLI 范围解释。

## 从真实问题建立用例

优先选择用户纠正过的失误、反复返工、误触发、遗漏动作和未经确认的范围扩张。为每个案例保存：

- 尽量保留原意的自然请求，以及来源和目标故障。
- 脱敏、可复现的初始文件或数据，明确外部依赖。
- 可观察的正确结果，以及必要的过程或副作用限制。
- 该案例属于回归保护、能力探索，还是留作未参与调优的检验。

同一故障机制保留有代表性的案例，补一个改变关键条件后“应当不做”的对照，按实际需要覆盖缺口。少量案例可以起步，测试数量由风险和证据缺口决定。

把案例放在所属 Skill 的 `evals/evals.json`，字段沿用 [schemas.md](schemas.md)；本地初态放 `evals/fixtures/<case>/`。可加 `fixture`、`fixture_renames`、`sandbox`、`tags`、`source` 描述执行和来源。样例 Skill 用 `SKILL.md.fixture` 保存，运行时在临时项目内还原，避免测试数据进入实际发现目录。跨 Skill 用例放在主要行为所有者的集合中，并记录涉及的组合，保持一份权威定义。

把已知错误版本或明确错误产物交给检查器，确认它能够识别目标失败；缺少历史版本时，记录尚未建立的证据，使用针对该机制的错误产物检查评分条件。已有一次通过的案例可以作为回归用例的起点，稳定性需要后续独立运行积累。

## 选择最低充分的运行方式

能从差异、类型、链接或脚本单测证明的内容，使用确定性检查。纯表达质量可以评审固定材料；故障发生在触发、工具调用、文件修改或交接时，运行新上下文任务。

只有失败依赖多轮交流时，才安排固定用户回复的多轮测试。用户模拟 Agent 适合真实互动变化本身是评估对象的情况。一次局部文案改动不会自动升级为多会话实验。

每次运行使用独立初态，外部数据使用脱敏记录或本地替身。日期、随机性和外部状态影响判断时，固定其输入或明确容差依据。生产副作用使用受控测试环境；文件沙盒不代表外部工具已隔离。

## 先看结果，再看必要过程

代码检查适合文件增删改、结构、返回值、数据状态和明确契约。语义、设计质量与表达用有证据的人工或模型评审。

把“好不好”拆成少数具体判定。例如规格评估可以检查：确认事项是否遗漏、候选是否冒充需求、未决事项是否仍未决、是否保持已有文档归属。每项给出通过、失败或证据不足，并引用实际产物。

工具轨迹用于确认必要动作、真实调用和越界行为。允许不同但合理的执行路径；固定工具名、次数或顺序仅用于这些因素本身属于契约的情况。正文出现“已完成”或“不会修改”不足以证明结果。

运行超时、环境失败、产物无法读取属于执行或证据问题；实际产物违反目标属于行为失败。能够确定期望产物根本未生成时，属于行为失败。证据不足的主观判断保留为无法判断，补足证据后再进入二元评分汇总。

模型评分器优先使用独立、明确的判定项，并以理由和引用支撑结果。重要或有争议的判断使用用户已确认的标准、人工样本或盲评校准。技能作者自己的肯定结论不能单独证明质量提升。

## 判断改善与持续维护

先检查原有底线是否退步，再看目标能力是否改善，最后比较耗时、token、工具调用和用户介入。缺少可靠价格时报告 token 与时间，费用保持未知。

报告每个案例和每次试验的结果；保留失败重试记录。不同结果会影响采用决定时，增加重复或保留案例检验；一次胜出不构成统计结论。所有案例总是同过或同败时，检查案例是否仍能区分目标能力。

回归集守住已经采用的行为契约；能力集保留尚未稳定解决的真实难题；留出案例用于检查是否只适应了已知例题。依据真实使用持续补充，按本次改动选择相关案例运行。稳定性和契约未改变时继续复用原标准；需求变化时记录标准为什么改变。
