# 三个独立候选

只读评审，各目录的before.py/after.py代表各自完整实现，不要求各候选使用相同内部结构。Python标准库即可检查。

A需求：把事件接收从历史影子写入改成直接正式保存，整体替换部署。所有调用方都在代码中；影子迁移已结束，没有旧客户端、在途旧消息或回滚格式要求。清理本次替换涉及的影子分支和开关是已确认交付范围。测试只检查接收后result中有事件，当前before/after都通过。

B需求：给既有worker增加新消息字段eventId，并继续消费旧生产者的id字段。两个生产者在本周滚动发布期间同时运行，回滚窗口到本周末。当前队列可以为空，但旧生产者仍可随时发送；同一调用点也是回滚版本的生产入口。下周确认旧生产者已全部退出并关闭回滚后删除旧字段解码。处理事件的业务逻辑保持不变。

C需求：公共SDK长期承诺同时接受id与eventId两种字段；旧字段是持续支持的公开协议，没有退役计划。本次只整理解码调用结构，保持两种格式都可用。单个库进程内调用，没有队列和部署切换。
