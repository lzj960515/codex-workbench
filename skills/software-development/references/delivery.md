# 交付与证据

本页用于开发流程收尾，确认现在已经取得什么结果，以及哪些后续状态仍未得到证明。

## 复用已有证据

核对最终差异是否属于已确认目标，实际验证和独立审查是否覆盖当前版本。已有证据仍有效时直接使用；后续修改影响了被验证的性质，再补对应检查。

选择最低成本的充分证据。测试、类型检查、构建、目标调用和直接内容核对各自证明不同性质；独立审查检查方向、契约与实现，不能替代实际执行结果。通过某项检查也不证明模型必要性或新增行为已获确认。

代码修改、检查结果与审查结论分别记录。检查被跳过、环境失败、工具不可用或审查尚未完成时，说明影响哪项完成判断，交付保持与证据相称的状态。

核对证据对应的版本、对象和环境。检查重试后通过、带有告警或只有部分覆盖时，判断它是否仍足以支持当前结论；需要说明的限制保留在交付结果中。

## 按实际任务核对状态

| 准备报告的状态 | 对应的直接证据 |
| --- | --- |
| 设计完成 | 用户目标、既有契约、推荐模型和实质取舍，剩余未知保持明确 |
| 本地代码完成 | 最终代码与差异、相称的验证、独立审查结果；原要求已完成且重要问题已解决 |
| 检查通过 | 对当前相关版本实际执行的命令、退出结果及检查范围 |
| 已提交、已推送 | 本地提交记录，以及目标远端实际包含该提交的事实 |
| 已创建或合入合并请求 | 对应平台的当前请求、分支与合入状态 |
| CI、制品、部署或线上有效 | 当前目标版本对应的流水线、制品、部署记录或直接业务结果 |

只核对本次需要报告的状态。本地实现、提交、推送、部署与线上结果分别成立，按照当前授权推进各自环节。

## 保持收尾清楚

- 从目标解释完成了什么，再说明必要验证和独立审查结论。
- 使用具体的剩余边界，例如“本地构建通过，尚未部署”，让用户可以判断下一步。
- 审查问题已解决且直接证据充分时结束。每一项后续检查都应对应尚未证明的重要性质或实际新变化。
- 项目约定需要更新文档时，沿既有文档所有权记录当前事实与决策，保持说明与代码一致。

这份参考承载开发任务的收尾。文档、运营、发布与线上恢复等任务在各自流程中核对相应对象和环境的直接结果，复用已经成立的证据。
